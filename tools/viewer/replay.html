Block Replay

Stage 6 run: the grid fails and one survivor keeps the generator going.

How this is simulated
  1. The C++ simulation steps the whole world every half game second: commands first, then each system in a fixed order (items and map, actions, power, body), then scheduled events like the grid failure.
  2. The survivor is driven by a small script that sends the same commands a player's clicks would send ("drink at the sink", "start the generator"). The simulation decides how long each takes, how far the walk is, whether it's possible, and what it costs the body.
  3. Everything on this page was recorded from that run (a frame per game minute, the noise and light fields every game hour). This page only replays it; it doesn't simulate anything itself.
  4. With the dead on: sixty neighbours each have a drawn fate (fled, dead, walker at home, walker somewhere off the map). Walkers off the map arrive at the edges, more often while the generator's noise and lit windows reach past the block. A walker hears and sees with the same noise and light fields shown here, walks to what it noticed, pushes on doors and windows part by part until they give, grabs and bites. A bite may carry the infection; the bitten die on a drawn schedule and rise with what they had.
  5. The tests run scenarios like this one and check the numbers against real references: fuel use against generator spec sheets, how far the generator is heard against the night background, how long fridge food keeps.
